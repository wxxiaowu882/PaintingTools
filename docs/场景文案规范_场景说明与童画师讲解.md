# 场景文案规范 · 场景说明 × 童画师讲解 × 标注

> **这份文档是干嘛的**：以后写/改几何体·静物（及同类沙盒）场景的「列表简介」和「进场景必读正文」时，都按这里来，避免靠聊天记忆。  
> **什么算权威（重要）**：  
> 1. **当前已上线 / 生产端里的实际场景**（`docs/json/沙盒_*` + 生产工具里的现状）——场景怎么摆、讲什么、编号怎么排，以现状为准。  
> 2. **本文**——只管「场景说明 / 童画师讲解 / 标注」怎么写、怎么配合；并约定历史债处理与专业纠偏。  
> 3. **下列旧稿默认不作设计依据**（多已过时，现网场景已有较大变动）：`场景规划设计.md`、`几何体场景设计草案.md`、`几何体场景设计.md`、`几何体场景设计_舞台版本.md`；`站点规划_访谈与路线图.md` 只作站点级目标备忘，**不约束**单个场景怎么设计。写文案时若旧稿与现网冲突，**跟现网、跟本文**。  
> **修订日期**：2026-08-02  
> **已定显示名**：消费端 / 生产端对外文案统一叫 **「童画师讲解」**（原「本场景要点」词不达意，弃用对外叫法）。

---

## 1. 一句话结论

| 块 | 它是什么 | 它不是什么 |
|----|----------|------------|
| **场景说明** | 列表里扫读用的**短简介** | 不是本场景知识正文 |
| **童画师讲解** | 进场景**必看**的知识正文：我要通过本场景向学员传达的内容 | 不是一句口号、不是「定调子」 |
| **场景内标注** | 围着讲解转的**落地配合**（指哪儿、看什么） | 不是另开一堂课，也不和讲解抢同一段总结 |

三条拧成一句话：**列表勾兴趣 → 讲解把知识讲透 → 标注让眼睛对上号。**

---

## 2. 字段与产品位置（写文案时要分清）

### 2.1 生产端字段（JSON / 编辑器）

| 用户看到的名字 | 写入字段 | 放哪 |
|----------------|----------|------|
| 场景说明 | `meta.detail` | 左栏列表旁的短文本 |
| 童画师讲解 | `meta.keyPoints`（纯文本）+ 可选 `meta.keyPointsRich`（富文本） | 右栏正文；消费端固定入口阅读板 |
| 场景类别 | `meta.category` | 与目录归类一致（几何体 / 色彩 / 氛围 / 构图 / 几何体写生 / 静物写生 等） |

> **约定**：对外显示名改叫「童画师讲解」；**内部字段名暂不改**（仍用 `keyPoints`），避免无谓牵动全站。改 UI 文案时生产端、消费端、按钮 `title` / 面板标题一起改齐。

### 2.2 谁在什么时候看

- **场景说明**：还在目录里时看；决定「要不要点开」。  
- **童画师讲解**：点进场景后**应当先看**（引导 → 讲清 → 收束 → 接下文）；可反复打开，不是一次性弹窗。  
- **标注**：转视角、对照模型时看；短标签 +（必要时）详细说明，服务讲解里已经钉死的那一点。

---

## 3. 「童画师讲解」的宗旨（最高优先级）

**童画师讲解 = 我想通过本场景向学员传达的知识。**

它相当于整场的知识载体，必须同时尽量覆盖（可长短不一，但意图要全）：

1. **引导** — 进来先看什么、怎么看（不训人、不施压）  
2. **知识说明** — 本场景真正要讲清的内容（可以多段，不限于一句口号）  
3. **总结** — 学完带走什么（能复述、能迁移）  
4. **铺垫** — 和下一个场景怎么接（链条感，而不是孤立卡片）

### 3.1 合格 / 不合格

**合格**

- 学员只读这一块，也能说清「这一关学会了什么判断 / 什么看法」。  
- 和场景里看得见的证据对得上（不是空讲）。  
- 空字段要补；已有但只剩口号、跑题、或和标注重复同一段总结的，要重写。

**不合格**

- 只有氛围句、鸡汤句，没有可带走的知识。  
- 把本该在讲解里的正文，整段塞进某条红色「★ 总之」标注里（讲解空着或极短）。  
- 一口气讲多个互不统属的知识点（主线索糊掉时，优先砍讲解，而不是硬塞）。  
- 列表说明写得像操作手册（点哪、关标注等）——这类进场景后再讲。

### 3.2 语气（和品牌一致）

- 自称语境：**童画师吴晓**在讲；温暖、邀请，**欢迎感，不训人**。  
- 术语先人话，再给名字。  
- 不搞「每天打卡练」式营销；要的是看得懂、记得住、愿意收藏分享。  
- 大白话优先；该精炼就精炼，不堆说明书腔。

---

## 4. 「场景说明」怎么写

- **位置**：只服务目录扫读；短、分行、一眼抓住。  
- **默认结构（三行内为佳）**  
  1. 一句钩子（为什么在乎）  
  2. 一句用 `<b>...</b>` 钉死的**本关主线索**（能加粗就加粗；不要为了「唯一判断」硬套旧模板）  
  3. 可选：一句引路（别写成操作步骤）  
- **允许**：换行；仅 `<b>` 强调。  
- **禁止**：堆标签字段（入门/分钟/收益等）；在列表里写「点写生 / 拖光 / 关标注」等操作说明。  
- **和讲解的关系**：说明是「门上的牌子」；讲解是「进门后的展板」。说明里出现的关键句，应能在讲解里被展开，而不是两套互相打架的说法。  
- **跟现网**：某一类场景在现网里已经形成自己的说明口吻时，优先对齐同类现网场景，而不是对齐过时设计稿。

---

## 5. 结构按场景类型（不定死一套四段模板）

约定：**不强制每个场景都写成固定四段标题**；按**现网实际类别 / 编号习惯**选骨架，但 §3 的四种意图（引导 / 知识 / 总结 / 铺垫）在合适处要落下来。  
下面分类是按当前沙盒目录常见形态写的**工作提示**，不是旧设计稿的强制课表；某一类现网做法已经变了，以现网为准，并回写本节。

### 5.1 入门 / 导览（如 `001` 欢迎、`002` 以简驭繁）

- 偏欢迎 + 世界观 +「你接下来会碰到什么」。  
- 讲解可以稍长；标注以「举例指认」为主，**不要把总结再写进一条大标注里**。  
- 铺垫：指向学员接下来更可能点开的那一类（以现网目录顺序为准）。

### 5.2 万物观察法 · 单形体步骤链（球/方/柱/锥/棱… 步骤一～三、最深处、虚实等）

- 优先对齐**同形体相邻编号**的现网讲法；讲解把「看哪里、看什么变化」写清。  
- 引导句短；知识段是主体；结尾用一两句接到现网里真实的下一步（不要按过时课表硬接）。  
- 标注：对准证据点，用词与讲解一致。

### 5.3 构图 / 色彩 / 氛围专题

- 讲解先钉本关主看法；对比、口诀可进讲解。  
- 场景说明更要短、钩子强。  
- 标注负责指出对比双方或关键区域，不复述长文。

### 5.4 几何体写生 / 静物写生

- 讲解偏「怎么看这组东西」+ 可带走的观察顺序；可提示写生模式价值（关标注自己看）。  
- 操作细节仍以进场景后的讲解/标注为主，不塞进列表说明。  
- 铺垫：按现网同类场景的真实衔接来写，不虚构旧稿里的「下一环」。

### 5.5 其它 / 综合类

- 先看该场景自己已经摆了什么、标了什么，再反推讲解该讲什么。  
- 少引入和画面证据对不上的新概念；总结仍归讲解，标注只做索引。

> 某一类型写多了若形成固定小节标题（如「先看」「记住」「下一站」），可以沉淀回本文档，但**先跟现网内容，后沉淀模板**。

## 6. 标注如何配合讲解

- **从属关系**：讲解是统领；标注是附件。改讲解时，顺带检视标注是否过时、重复、抢戏。  
- **短标签**：指认对象或现象（「圆柱体」「交界线」）。  
- **详细说明**（标注的 `detailText` 等）：需要时再展开类比/补充；不要把整篇讲解搬进一条标注。  
- **建议交付物**（做文案优化时）：除两段正文外，可附「标注改写建议」（改哪条、删哪条、语气怎么收）；需要落地时再给可粘贴清单。

### 6.1 历史债：讲解正文曾写在「经典标注」里（必查、必迁）

早期版本还没有「童画师讲解」字段时，有些场景会把**本该是整场知识正文**的内容，写进场景里的一条（或几条）**经典引线标注**。这是已知历史债，优化场景时**默认要主动排查**，不靠用户逐条点名。

**常见识别信号（满足多条更可疑）：**

- 篇幅明显长于同场景其它标注  
- 语气像总述 / 收束 / 练习指令（「总之」「请你找出」「记住」「掌握…即可」等），而不是指认某个局部  
- 颜色或位置像「总述牌」（如醒目红、★ 开头），不像普通指认  
- `meta.keyPoints` 为空或极短，但标注里已有完整论述  

**处理步骤：**

1. **主动发现**：同时读 `meta.keyPoints` 与全部标注的 `text` / `detailText`，用判断识别「这其实是讲解正文」。  
2. **移植**：迁入 **童画师讲解**（`keyPoints` / `keyPointsRich`）。  
3. **优化**：按 §3 重写——补引导、理顺知识、收束、接下文；**不是原样粘贴完事**。  
4. **善后标注**：原总述标注改为短指认、删除，或只留与局部证据相关的一句；**禁止**讲解与标注各留一份完整总结。  
5. **两边都有时**：以「哪套更贴近本场景画面证据、更符合 §3」为准合并优化，去掉重复那一侧。

> 例：`002` 一类场景里，红色「★ 总之，复杂世界都是由简单几何体构成…」长标注，即属本条对象。

## 7. 和业务目标的对齐（写的时候心里要有数）

- 访客要感到：这是 **童画师吴晓** 设计的学习场景，有路径、能学会，不是冷冰冰工具页。  
- 几何体·静物线服务「观察入门 → 可迁移到静物/肖像」；文案要帮品牌记住所教的路径，而不是堆术语。  
- 内容权威在**生产工具生成的 JSON**；文案定稿后在生产端写入并发布，**避免手改已发布 JSON 当常态**（紧急修正也要回到生产端闭环）。

---

## 8. 专业纠偏：把教学体系当作活的作品来完善

写文案时，协作方不只做「填字段」，还要以**专业艺术家 / 教学设计者**的眼光，随时审视这套场景教学体系，发现问题就提出，并尽量当场收进该场景交付（需要定规矩的则回写本文）。

**随时可纠的方面（不限于纯文案）：**

- **观察与造型**：术语是否先人话后术语；形体 / 光影 / 边缘是否说准；有没有和画面证据打架。  
- **教学节奏**：本关主线索是否清晰；是否过载；和相邻场景是重复、断层，还是接得上。  
- **审美与呈现**：标注是否吵画面；总述是否抢戏；说明 / 讲解是否像说明书，而不是「欣赏中学习」。  
- **路径感**：学员读完是否知道「学会了什么、下一眼看哪」；品牌语气是否仍是童画师吴晓（欢迎、不训人）。

**怎么落地：**

- 发现不足 → 在该场景交付里直接改文案 / 给标注与结构建议；需要成文定规矩 → **补进本文修订记录**。  
- 不替用户擅自改生产 JSON（除非明确要求落地）；但**必须主动指出**，不能假装没看见。  
- 纠偏优先级：先让「童画师讲解」站住 → 再收标注与说明 → 再提体系级结构调整建议。

## 9. 协作时怎么推进（我们以后按这个干活）

### 9.1 单场景交付检查清单

写完或优化一个场景时，自问：

1. 场景说明是否短、有钩子、有加粗主线索、无操作说明书？  
2. 童画师讲解是否能单独讲清本关知识，并含引导 / 收束 / 下节钩子（按类型可有侧重）？  
3. 是否已排查「讲解正文藏在经典标注里」的历史债？该迁的是否已迁入讲解并优化，标注是否已去重？  
4. 标注是否服务于讲解、无重复长总结？  
5. 是否跟**该场景现网内容**一致（模型、标注、相邻编号），而不是跟过时设计稿一致？  
6. 语气是否欢迎、是否先人话后术语？  
7. 以专业艺术家视角：本场景在观察、节奏、审美、路径上有无明显漏洞？有则是否已提出纠正？

### 9.2 建议工作顺序

1. **先读现网**：该场景 JSON 的 `name`、`meta`、**全部标注文案**，以及目录里前后相邻场景——这是设计真相来源。  
2. **先判历史债**：`keyPoints` 空/弱 + 标注里有总述长文 → 按 §6.1 移植并优化进童画师讲解。  
3. 再写/改 **童画师讲解**（定知识），再压 **场景说明**，再给 **标注善后建议**。  
4. 顺带做 §8 的专业纠偏（能当场改的改，需定规矩的回写本文）。  
5. 成批做时：按现网类别或编号段推进；新类型先共创 1 个样板定文风，再复制节奏。  
6. UI 上「本场景要点」→「童画师讲解」的改名，与首批文案落地可分开排期，但**对外口径以本文为准**。  
7. 发现旧稿与现网冲突时：改文案跟现网；有必要再把结论补进本文，**不要回头去「修好」过时设计稿当依据**。

### 9.3 变更本文档

- 叫法、字段分工、不合格标准、历史债处理规则、纠偏原则变了：必须改本文，并在下方「修订记录」加一行。  
- 只改某个场景的具体句子：不必改本文。
