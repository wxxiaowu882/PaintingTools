# 亚洲头部肌肉 × Base15 对照任务 — 规则与验收

> **适用范围**：`work_v4/` 下全部几何迭代、Blender 渲染、对照审阅页与交付物。  
> **权威参考**：Base15 六视图画稿（`Base15_正.png` 等）及 `compare_review/base15/`。  
> **协作原则**：任何一轮声称「可以看了」的成果，必须先过 **AI 自测**；自测不过，不得请用户验收。

---

## 1. 交付前必须 AI 自测（硬性）

**每次**产出或更新候选版本（如 `SHELL_v8`）后，AI **必须**在本地跑完自测门禁，**全部 mandatory 项 PASS** 后，才能向用户汇报「请验收」。

- **禁止**：只改代码/渲染、未跑自测就交差。  
- **禁止**：自测 FAIL 时用「你先看一眼」搪塞。  
- **允许**：optional 项 WARN（如侧视 profile 细比例未达标），须在汇报中**明确标注**，并说明不阻塞本轮、后续版本再改。

### 1.1 一键自测命令

```bash
python work_v4/scripts/selftest_primary_review.py SHELL_v8
```

将 `SHELL_v8` 换成当前候选 ID。退出码 `0` 且输出含 `[SELFTEST PASS] mandatory gates` 方可交付。

### 1.2 启动对照页（自测 smoke 依赖）

```bash
# Portal 入口
自用工具文件_不部署/0_Portal/12_亚洲头肌对照页.bat

# 或手动
cd work_v4/compare_review && python -m http.server 8765 --bind 127.0.0.1
```

浏览器访问：`http://127.0.0.1:8765/`（**禁止** `file://`）。

## 2. AI 自测内容（与用户对图时的标准一致）

### 2.1 截图来源、对齐与同向

| 要求 | 说明 |
|------|------|
| **必须从 3D 正交视图渲染** | 对照页上的成果图来自 Blender EEVEE 正交相机输出（`rerender_compare_views.py` / `common.render_views`），**不得**用 2D 拼贴、Photoshop 手工改轮廓冒充 3D 截图。 |
| **大型对齐** | 正 / 侧 / 背主审三视：头顶、下巴与 Base15 **对齐**（对照页并排、拖拽模式同一显示尺度）。 |
| **朝向一致** | 模型朝向与 Base 画稿**同向**（尤其侧视不能镜像）。侧视在 3D 渲染后若与 Base 约定相反，允许 **水平翻转 PNG**（仍算 3D 截取的后处理，须在脚本中固定，不可手改单张图）。 |
| **相机视角一致** | 主审三视使用与 Base15 一致的**正交机位表**（`common.VIEW_SPECS_PRIMARY`：正 0°、侧 ±90°、背 180°）；辅助视角（前侧/后侧）仅参考，不作大型比例硬结论。 |

**自测脚本**：`verify_view_direction.py`（朝向/侧视镜像）、`selftest_compare_align.py`（像素级顶底对齐）、`verify_render_visual.py`（**mandatory**：与 Base 比 shading/配色/直方图/额部色相）、`verify_render_exposure.py`（辅助统计）、`compare-review-align-smoke.js`（网页端 flat/色差复检）。

### 2.2 背景、3D 预览与色彩

| 要求 | 说明 |
|------|------|
| **白底** | 对比图背景与 Base 一样，必须是 **#FFFFFF**。渲染后用 `whiten_png_background.py` 强制白底（Blender 内无 PIL，须走**系统 Python** subprocess）。 |
| **3D 预览白底** | 对照页「3D 预览」模式：`scene.background = 0xffffff`；容器背景也为白，不用深灰衬底造成「发灰」错觉。 |
| **肌肉色彩** | 每块肌肉色相/明度须与 Base 图**同一套**（`Q8.force_recolor()` + Filmic 曝光约 **-0.8**、低强度三点光）。不得灰底、不得正脸严重过曝（肌肉糊成一片白）。 |
| **层次/shading** | 须有与 Base 同量级的明暗层次（不能 flat 色块贴图感）；自测比 **fg 标准差** 与 **直方图 L1 距离**。 |

### 2.3 正 / 侧 / 背大型比例

主审三视的**大型比例**（头高宽比、颅顶段、枕部等 silhouette 级）须与 Base 各视角**一致**。

- **优先看**：正、侧、背（用户主审视角）。  
- **验收方式**：对照页并排 + 拖拽，顶底对齐后比整体轮廓与占比。  
- **量化门禁**（侧视）：`base15_proportion_eval.py` — hw_ratio、vault、occiput、profile_rmse 等；当前为 **optional**，profile 未达标时标 WARN，不替代肉眼主审，但不得隐瞒。

### 2.5 正交视图（禁止明显透视）

- **必须**使用正交相机（`cam.type = ORTHO`），与 Base15 设计稿一致。  
- **禁止**带明显透视的透视相机截图用于主审对照。  
- 若引擎/抗锯齿带来**极细微**边缘差异可接受，但不得出现「近大远小」导致大型比例误判。

## 3. 迭代顺序：先大型比例，再局部

1. **第一阶段 — 大型比例**  
   - 头壳 / 颅顶 / 枕部 / 侧视 hw 等 silhouette 级问题。  
   - 每步只改**一个**变量（如侧视 scale、枕部 bulge），重渲主审三视，跑自测。  
   - 用户确认主审三视「大型对了」再进入下一阶段。

2. **第二阶段 — 局部与肌肉细节**  
   - 分区肌肉形态、咬肌、额颞等局部。  
   - 仍须保持 2.1–2.3 全部成立；改局部时**回跑主审三视自测**，防止侧视又镜像、白底又变灰。

3. **版本命名**  
   - 几何 checkpoint：`SHELL_vN`（只增不覆盖已验收版本）。  
   - 废弃坏例（如球形 `SHELL_v2`）不得 promote 为默认候选。

## 4. 防回归：改一处不能坏另一处

| 原则 | 做法 |
|------|------|
| **最小 diff** | 只改与当前单点目标相关的脚本/参数；禁止顺手「优化」无关渲染、UI、注释约定。 |
| **单步验收** | 每步约定验收范围（例：「仅验证侧视朝向 + 白底」），通过后再做下一步。 |
| **必跑自测** | 任意改动影响渲染、相机、色彩、对齐或对照页后，**完整跑** `selftest_primary_review.py`。 |
| **保留 workaround** | 注释中标明天坑/致命修复的代码（如侧视 flip、whiten subprocess）不得删，除非等价替换并自测通过。 |
| **对照页默认候选** | 更新 `compare_review/manifest.json` 的 `default_review` 时，须该版本已 mandatory PASS。 |

### 4.1 Mandatory 与 Optional 门禁一览

| 类别 | 项目 | 脚本 |
|------|------|------|
| **Mandatory** | 主审朝向（正/侧/背，侧视非镜像） | `verify_view_direction.py` |
| **Mandatory** | 视觉 vs Base（白底/shading/配色/直方图） | `verify_render_visual.py` |
| **Mandatory** | 曝光统计（辅助，不单独代表 PASS） | `verify_render_exposure.py` |
| **Mandatory** | 顶底像素对齐 | `selftest_compare_align.py` |
| **Mandatory** | 对照页网页 smoke（含 flat/色差） | `compare-review-align-smoke.js` |
| **Optional** | 侧视严格比例 / profile RMSE | `base15_proportion_eval.py` |

### 4.2 重渲主审截图（几何不变时）

```bash
"D:/Blender 5.0/blender.exe" --background --python "work_v4/scripts/rerender_compare_views.py" -- SHELL_v8
```

渲染结束须看到 `[whiten]` / `[whiten+flip]`，主审五视须见 `[grade]`；若出现 `[warn] whiten skip (no PIL)` 视为**失败**。

**渲染管线要点（2026-08-23）**  
- 重渲时 **禁止** 反复 `force_recolor`（会洗坏贴图）；`prepare_compare_render(recolor=False)` 为默认。  
- 三点光：Key 95 / Fill 6 / Rim 38，Filmic 曝光 **-1.15**，主审分辨率 **1600**。  
- 3D 出图后：`whiten` → `grade_to_base15`（仅前景色调对齐 Base，不改几何）；正脸额外收紧**额部**色带。

## 8. 自测漏检复盘与防再发（2026-08-23）

### 8.1 用户能看出来、旧自测却 PASS 的原因

| 用户肉眼问题 | 旧自测为何漏掉 |
|--------------|----------------|
| 正脸「糊成一片白 / 没层次」 | 只查 **全局 mean/p95** 和 **≥250 像素占比**；SHELL_v8 mean≈158 在宽容差内，且无 250 纯像素 → 误判 PASS |
| 肌肉配色与 Base 整体不对（额部绿/紫对调） | **从未与 Base 比直方图、分区色相** |
| flat 色块、不像 Base 的 soft shading | **未比 fg 标准差**（ours≈13 vs Base≈32，差 3 倍） |
| 并排对照页上一眼假 | smoke **只测顶底对齐**，不测「像不像 Base」 |

**结论**：旧门禁验证的是「数值没爆表 + 对齐」，不是「**看起来像 Base15**」。这是交付事故，不是用户挑剔。

### 8.2 防再发策略（必须遵守）

1. **与 Base 对照，不单看绝对值**  
   mandatory 新增 `verify_render_visual.py`：主审三视分别与 `base15/{view}.png` 比 **std 比、p95 比、mean 差、直方图 L1**；正脸额外比 **额部 hue**。

2. **网页 smoke 二次拦截**  
   `compare-review-align-smoke.js` 在拖拽模式下对 **ours vs base** 算 stdMin、meanΔ，拦截 flat 与整体色差。

3. **禁止「单项 PASS 就交付」**  
   `verify_render_exposure.py` 保留作辅助日志，**不能**单独作为色彩 PASS 依据。

4. **自测 FAIL = 不得请用户看**  
   修复渲染/配色 → 重渲 → 完整 `selftest_primary_review.py` → 全 mandatory PASS 后再汇报。

5. **新增用户级问题必须补门禁**  
   用户指出旧自测未覆盖的缺陷，须先加/收紧脚本阈值，再修图；避免同一类漏检重复发生。

6. **汇报须附自测摘要表**  
   列出每项 mandatory 结果；若有 FAIL 须写清哪条指标、数值多少，禁止只写「已自测」。

## 6. 给用户汇报时的最低信息

自测 PASS 后，汇报须包含：

1. 候选版本号（如 `SHELL_v8`）。  
2. Mandatory 自测结果摘要（朝向 / **visual vs Base** / 对齐 / smoke）。  
3. Optional WARN（若有）。  
4. 请用户 **Ctrl+F5** 强刷对照页，主审 **正 / 侧 / 背** 并排与拖拽各看一遍。  
5. 本轮** deliberately 未改**的范围（避免用户担心被顺带改坏）。
