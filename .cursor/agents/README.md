# 模式 1：Subagents 协作（本仓库定稿）

主 Agent 当项目经理；自定义角色只按**工序**分工，不按电子书 / 3D / 文案等业务模块拆角色。领域约束继续靠 `.cursorrules`、`.cursor/rules/*`、`docs/`。

**默认自动执行**：见 `.cursor/rules/mode1-subagents-default.mdc`（`alwaysApply`）。你只需说业务目标，不必另写「先规划 / 再验收」类提示语。

## 角色

| 角色 | 文件 | 职责 |
|------|------|------|
| （内置） | Explore / Bash / Browser | 主 Agent 按需自动调用 |
| **planner** | `planner.md` | 复杂任务拆单点、写验收标准；只读；复杂任务主动派 |
| **主 Agent** | 当前聊天 | 按计划实现；打回循环；向用户汇报 |
| **verifier** | `verifier.md` | 主动 code review + 功能测 + 浏览器 + AI 视觉；不改业务代码；清理过程文件；交付前主动派 |

不设独立 implementer / 业务域 Agent。

## 默认流水线（无需用户点名）

1. **小任务**（单点清晰）：主 Agent 直接做 → **自动** verifier；跳过 planner 时须一句说明。
2. **复杂任务**：主 Agent **自动**派 planner → 逐步实现 → 每步或整单后 **自动**派 verifier。
3. **打回循环**：verifier 不通过 → 主 Agent 改 → 再验。**无轮数上限**；直到通过，或用户说停。
4. **进度汇报**：每完成一个单点、每一轮验收后，主 Agent 须向用户说明：做了什么、结果、卡点、下一步。

## 可选显式调用（一般不需要）

```text
/planner …
/verifier …
```

或：「跳过规划」「不用验收」「停」。

## 验收要求（verifier）

- **主动**开浏览器、截图、AI 视觉读图（需要页面/3D/标注时），不是「碰巧有图才看」。
- 同时做代码 review 与功能验证。
- 标注类禁止只靠探针/日志宣称通过（见 `.cursor/rules/ai-vision-qa.mdc`）。
- 造形硬结论：用户终审。

## 过程文件清理

- 主 Agent 与 verifier：**及时删除**无用截图、临时输出、调试过程文件（只要不影响后续步骤）。
- 浏览器产物优先落在 `.cursor/browser-automation/runs/`；最终只留有价值证据。
- 不要把一次性过程文件散落到仓库业务目录。

## 断网 / 换号接续

- **同会话**说「继续」即可，依赖聊天记录；**不强制**任务状态文件。
- 若新开聊天还要接着干：把未完成要点贴进新对话，或口头说明即可。

## 与模式 2（Projects）

本仓库默认用模式 1。模式 2 依赖账号侧长期 Project，频繁换号不划算；非用户明确要求不启用。
